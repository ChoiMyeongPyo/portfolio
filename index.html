삼성전자 AWS EKS 플랫폼 운영

대규모 AWS 환경의 서비스 플랫폼을 고객사에 상주하며 운영하고 있습니다. 개발·스테이징·성능검증·운영 4개 환경에 플랫폼 도구용 클러스터와 이중화된 서비스 클러스터로 구성된 EKS, 일부 서비스를 위한 ECS가 함께 운영됩니다. 인프라와 배포를 모두 코드로 관리하는 체계 위에서 클러스터 운영, 노드 보안 패치, 장애 대응을 맡고 있습니다.

한 일

  • Kubernetes(EKS)·ECS 기반 프로덕션 워크로드 운영
  • Terraform 기반 AWS 인프라 설계 및 관리 (IaC)
  • GitOps 기반 배포 파이프라인 운영 (Argo CD)
  • 클러스터 노드 무중단 업그레이드 및 보안 패치
  • 모니터링·로그·트레이스 기반 Observability 운영
  • 장애 분석 및 대응, 컨테이너 워크로드 보안 적용

변경 관리 방식

  • 인프라는 Terraform, 클러스터 내부 구성은 Argo CD로만 변경
  • 모든 변경은 PR 리뷰를 거쳐 반영
  • 개발 → 스테이징 → 성능검증 → 운영 순서로 승격
  • 서비스 클러스터는 A 반영·검증 후 B에 반영해 무중단 유지
  • 노드 이미지와 애드온 버전을 고정해 예측 가능한 교체

사용 기술AWS, EKS, ECS, Terraform, Argo CD, Helm, OpenTelemetry

금융권 하이브리드 클라우드 랜딩존 설계·구축

금융권 고객사의 첫 퍼블릭 클라우드 환경을 처음부터 설계하고 구축했습니다. 온프레미스 데이터센터와 Azure를 전용선으로 연결하는 하이브리드 구조로, 운영·검증·관리 환경을 분리하고 금융 보안 규정을 만족하는 네트워크와 접근 통제를 갖추는 것이 목표였습니다.

한 일

  • Azure 기반 하이브리드 클라우드 인프라 설계 및 구축
  • 운영·검증·관리 환경을 분리하는 계정·권한 구조 설계
  • 온프레미스 연동 네트워크 설계 (전용선, VPN, Hub-Spoke)
  • 방화벽 기반 네트워크 세그멘테이션 설계
  • 정책 기반 거버넌스 및 접근 제어 구성
  • 보안 로그 수집 및 SIEM 연동, 서버 보안 기준선 자동화

설계 기준

  • 환경 간 경계는 구독 단위로 나누고, 권한도 그 경계를 따라 부여
  • 모든 트래픽(Spoke 간, 온프레미스 간)은 Hub의 방화벽을 거치도록 설계
  • 보안 규정은 문서가 아니라 정책·네트워크·계정 통제로 구현해 자동으로 지켜지게
  • 새 서버에도 같은 보안 기준이 자동으로 적용되도록 기준선을 코드화

사용 기술Azure, ExpressRoute, VPN Gateway, FortiGate, Azure Policy, Entra ID, Splunk

물류 플랫폼 AWS·DevOps 운영 체계

물류 플랫폼을 운영하는 자사 서비스 회사에서 전사 AWS 인프라와 DevOps 도구 전반을 관리했습니다. MSA 환경으로, AWS의 ECS·EKS와 사내 IDC 서버를 ECS Anywhere로 묶은 하이브리드 구조였습니다.

한 일

  • Kubernetes(EKS)·ECS 기반 MSA 워크로드 운영
  • Terraform 기반 AWS 인프라 설계 및 관리 (IaC), 환경별 모듈 표준화
  • CI/CD 파이프라인 구축 및 운영
  • 모니터링·로그·APM 기반 Observability 구축 (Datadog)
  • SLO 기반 서비스 신뢰성 관리, 알림 체계 구축 및 장애 대응 자동화
  • AWS 네트워크 아키텍처 재설계, 고가용성 설계, 리소스·비용 최적화

운영 방식

  • 신규 인프라는 콘솔이 아닌 Terraform 모듈로만 생성
  • 서비스별 SLO를 정하고 스쿼드와 매월 지표 리뷰
  • 알림은 담당 채널과 티켓으로 자동 연결
  • 매월 비용 리뷰와 리소스 태그 점검

사용 기술AWS, EKS, ECS, Fargate, Terraform, Bamboo, Datadog
